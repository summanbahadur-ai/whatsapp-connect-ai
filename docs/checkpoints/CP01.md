## Decisions and implementation review

- Ruling: keep Boot's public liveness/readiness group names; they are not component
  details or secrets. Test health status and absence of components/details rather
  than an unnecessarily exact one-property JSON string.
- Ruling: generated/default users are excluded until database authentication exists;
  no temporary login route or hardcoded credential was introduced.
- Ruling: Windows PowerShell maps native stderr to ErrorRecords. The Maven helper
  permits those records but checks and propagates the actual process exit code.
- Maven test dependencies emit Mockito/Byte Buddy dynamic-agent warnings on this
  JDK. They do not fail the tests or affect application startup; no warning-suppression
  JVM flags were added. Configure test agents explicitly if mocking is added later.
- Inline review checked the small security/configuration/helper surface and tests.
  No review agent was delegated, following the project's instruction.

## User manual test

1. Open D:\whatsapp-connect-ai in VS Code. Install the recommended Java and Spring
   extension packs if not already installed; let Java import backend/pom.xml.
2. The backend has been left running for testing. Open:
   - http://localhost:8081/actuator/health — status UP, HTTP 200.
   - http://localhost:8081/api/account — unauthorized JSON, HTTP 401 (expected).
3. Run `.\scripts\maven.ps1 verify` from the project root: BUILD SUCCESS, 8 tests.
4. To start it later when port 8081 is free: `.\scripts\maven.ps1 spring-boot:run`.
   Do not start a second instance while the first is still using 8081. Ctrl+C stops
   an instance started in your terminal.
